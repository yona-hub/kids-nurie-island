# 素材制作と420枚への拡張

## 現在の改善候補と採用の境界

I17の`*-storybook-v2`候補はPaintingProfile version 3。全10の共有Bezier、意味groups、制作眼、旧対応を持つ。白目は白、色相を保った虹彩・同系の暗い瞳・白反射を自動で描き、未着色時だけ反射枠を表示する。手動ハイライトは廃止。姫だけ制作まつげ、男の子/動物/恐竜へ共通まつげを付けず、乗り物へ顔を付けない。

生成した顔なしショベル原画/ホーム島と、変えたgeometryは旧10枚とは別の対象hashである。新レビューの`author-technical`、QAの`pass:false`は人間の採用ではない。demoで確認できる候補と承認済みの本番出力を区別し、採用記録を流用しない。現在の日本語制作UIは旧masterを編集する方式で、v3のgroups/eyes/shadingの統合・保存・rollbackは未完了（B13）。

制作・検査・次の作業の正本は [統合計画](storybook-improvement.md)。旧作品は元ID/元描画を保ち、「改善版をつくる」で別作品へ色を引き継ぐ。削除した車の顔色は捨て、窓や車体へ対応させない。DB schemaとRegionPaintを変えず、metadataでrenderer/modeを識別する。

## 以下は採用済み旧10枚と制作履歴

ユーザーの更新指示により、10主題を画像生成の白黒原画へ差し替える。最新原画と生成プロンプトは `content/generated-lineart/prompts.json`、測定は `qa-latest.json`、各瞳と白く残せるハイライトの対応は `eye-region-map.json` に保存する。新IDは `gen-<subject>-vN`。公開カタログには技術QA・素材確認・承認hashが揃った新IDだけを載せる。人間承認は別工程であり、生成指示を承認と扱わない。

瞳は白い内部の独立した塗り領域とする。その内部のハイライト枠も別領域とし、瞳を塗っても白く残せる。自動ハイライト・陰影・質感は両方の領域で無効にする。新しい利用者向け見本は白黒のみ。着色debugは制作内部だけで利用する。

原画の形状を手描きのSVGへ差し替えず、原画の黒線contourと解析用の塗りmaskを分離する。幅24pxは目安、領域数は約の指定として実数と警告を残す。17〜24pxの個別例外には4×操作実測と部位ごとの判断を必要とし、原画maskで17px未満の主役は再生成の対象とする。17pxは制作時の暫定選別値であり、公開pathの再ラスタ化・距離測定方式の差だけで値が下回った場合は、元mask・同一pathの実操作・個別の確認理由を分けて記録する。一般の閾値は下げず、承認したexact値と原画・path・ID画像・操作証拠が一致する特定領域だけに例外を適用する。単なる閾値緩和で漏れ・極小・選べない領域を合格にしない。詳細は `docs/asset-pipeline.md`。

2026-10-07、ユーザーが新しい10枚の一覧を確認し「この10枚を正式採用する」と回答した。現在の10件は、その回答を根拠とする `human` 承認を持つ。確認者は「ユーザー（Codex会話）」、対象の原画・領域・素材hashは `content/generated-lineart/user-adoption.json` に固定した。制作UIで全領域・3画材のcheckboxを操作した記録ではなく、会話での正式採用の記録として区別する。以前の技術確認記録も保持する。

`eye-region-map.json`、原画解析QA、`analysis-review.json` の `humanApproved: false` は、解析・技術注釈自体を人間審査としないための記録である。これらの履歴は承認回答後も書き換えない。現在の公開可否は `content/templates/reviews/` の承認hashと現行QAで判定し、今回の採用回答の対象は `user-adoption.json` で照合する。

## 原画の追加

1. 12テーマのいずれかと一意な英小文字IDを決める。
2. 1600×2000で構図を作り、128px安全マージンを確保する。
3. 領域は24px以上の塗れる幅を目安にし、肌・金属・毛などを意味で分ける。不要な極小分割は画像生成による編集で減らす。
4. 白黒ラスタ原画を `compile_raster.py` で解析し、日本語素材・背景除外・線切れ候補を原画に基づき注釈する。QA後 `node tools/asset-pipeline/import.mjs <出力フォルダ>` で未承認登録する。原画と解析maskと実測証拠を分離して保持する。
5. `Region` の日本語名、素材、固定方向、seed、陰影、ハイライト、質感を設定する。ランダムな再推定を本体へ持ち込まない。
6. 原画・領域・素材・3画材の比較を確認し、原画欠け・背景漏れ・小領域・視認性・線の交差を直す。
7. 人間の確認者が制作UIで承認する。または、特定した一覧への明示的な会話での承認を、その範囲・発言・現在hashとともに記録する。生成依頼や無回答を承認とみなさない。
8. assets build・テストを実行する。`catalog.json` に承認済みの1件が追加される。

領域配列は後ろ→手前。ある領域を他の輪郭が覆う場合でも、実際に塗れる可視領域が必要。背景は領域として含めない。全領域を囲う大きな白い矩形は禁止。

公開後の既存ID・region IDはユーザー作品から参照されるため変更しない。領域ID・描画順・領域パスを変える場合は新しいtemplate IDで追加する。buildも以前の承認済みJSONと比較して同IDでの変更を拒否する。素材の陰影・質感など、領域構成を保つ修正は同IDの新revisionとして公開できるが、承認hashの再確認が必要。古い公式templateは、そのtemplateを使った既存作品の再描画に必要な限り保持する。

作品は論理template IDとregion IDを保存する。同IDで承認された素材修正は、次にオンラインで作品を開いた時に最新revisionを使う。編集中のエンジンへ途中で差し替えない。オフラインでは取得済みrevisionで再編集し、再接続後の次の読み込みで修正を取得する。色・画材・領域対応は変えないが、修正された陰影等の表現は最新の承認内容へ更新される。再現性は同じrevision・作品状態・画材の組み合わせに対して保証する。

公開URLは `id.<SHA-256>.json` / `id.<SHA-256>.png` / `id.<SHA-256>.svg`。カタログの `assetUrl` を解決し、固定ファイル名を本体で組み立てない。古いrevisionファイルはbuildで上書き・削除しない。固定URLは旧クライアントとカタログ掲載終了後の既存作品用aliasとして保持する。

## 背景とフレーム

背景は11種: まっしろ、あおぞらのしま、お花のひろば、夕焼けの海、ほしぞら、森のひろば、みらいのまち、うみのなか、宇宙空間、お城の庭、わくせいのだいち。みらいのまちはrobots専用、宇宙空間と惑星表面はspace向け。中央の情報量と彩度を抑えている。

フレームは21種: なし / シンプル白 / カラードット / 色のしずく / 虹と雲 / 星 / 波 / クレヨン / 色えんぴつ、および12テーマ別の装飾。すべて外周100px以内に描画し、主役の安全領域へ入らないことをピクセル検査する。

背景とフレームの原画は `scenes.mjs`、生成物は `content/backgrounds/`、`content/frames/`。本体向け一覧は `backgrounds.json`、`frames.json` であり、`white` と `none` が既定ID。

## 420枚制作に進む前の人間確認

- 10枚の顔・体形・機械構造・植物表現が自然で、意図しない既存IPへの類似がないか。
- 3〜8歳の子どもが説明なしで塗れる領域サイズ・線の読みやすさか。
- 肌・髪・毛・金属・ガラス等の仕上がりが過度に暗く/光沢になっていないか。
- 実際のスマホとタブレットで細い葉・歯・機械パネルを容易に選べるか。
- 背景とフレームを組み合わせても、主役や未着色部分が隠れないか。
- 制作担当、確認者、利用許諾、承認済みhash、修正履歴が残る運用か。

420枚は配信カタログの目標件数。アカウントの保存作品500件とは独立した制限であり、初回PWA導入時に420枚をまとめて取得することはしない。

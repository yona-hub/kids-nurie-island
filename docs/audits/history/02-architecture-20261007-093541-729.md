**A02-05 — 素材revisionを識別しない作品サムネイルが、素材更新後も残る**

- **Severity：P2**
- **修正必須：はい**
- **区分：素材更新と派生画像キャッシュの関連追加所見**

**根拠**

- `docs/pwa.md:32`は、同じ論理IDの素材修正を次回オンライン読み込みから適用する設計としている。
- `packages/persistence/src/local.ts:22`のサムネイル行には作品revision・クラウドversionがあるが、生成に使用した素材revisionがない。
- `packages/persistence/src/index.ts:599`は作品の版が一致すれば保存済み画像を返す。素材更新ではこの条件が変わらない。
- `packages/persistence/src/cloud.ts:44`と`:50`の画像パスも作品versionだけを識別する。
- `apps/web/src/pages/Gallery.tsx:59`は保存済み画像があれば再描画しない。一方、詳細表示・再描画では更新後の素材を取得する。

**再現方法と実測**

1. 現行の`gen-round-sports-car-v2`を使い、全領域を青・なめらかで保存する。実描画エンジンでサムネイルを生成し、別端末相当のサービスへ同期・キャッシュする。
2. 検証用コピーで領域ID・形状を保持したまま陰影・ハイライト・質感設定を変更し、カタログの素材URLを新revisionへ切り替える。作品状態は変更しない。
3. 実ローダーが新設定を取得したことを確認し、同じ作品状態を再描画する。その後、同期とサービス再起動を行い、サムネイルを再取得する。

素材変更はメモリ内のコピーだけに適用した。正式素材や承認記録の変更・追加承認は行っていない。

```text
作品version                         = 1のまま
実ローダーによる素材更新の適用       = true
更新後・再起動後に返された画像       = 更新前画像と同一
期待する再描画画像との画素差         = 18,676 / 128,000 pixels
比較条件                            = 320×400、RGBいずれかの差が8超
更新前画像                          = 47,831 bytes
更新後の再描画画像                  = 37,508 bytes
```

| 更新後の再描画 | `872a1c8dae47ee110` |

**影響**

同IDの素材修正が詳細表示・書き出しへ適用されても、作品一覧には旧仕上がりが残る。作品versionが変わらないため、通常の同期や再起動では解消しない。作品状態の損失は確認していないが、一覧と実際の再描画結果が継続的に食い違う。

**推奨修正**

サムネイルに生成元の線画・背景・フレームrevisionを記録し、現在解決した素材と一致する画像だけを採用する。不一致なら作品状態から再生成する。クラウド画像にも同じ識別を持たせ、ローカル画像の削除後に旧画像を再取得する経路も防ぐ。

**再テスト項目**

- 作品versionを変更せず、同IDの線画素材・背景・フレームを更新する。
- 更新前画像を持つ端末、別端末、再起動後で一覧と詳細の描画が一致する。
- 新しい画像が未送信・送信失敗の場合、旧素材の画像を最新として採用しない。
- 旧素材で開いたままの端末から画像が遅延送信されても、新素材の画像を置き換えない。
- オフラインでは実際に使用できる素材revisionと画像の対応を保ち、再接続後に更新する。

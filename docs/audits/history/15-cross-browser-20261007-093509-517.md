**A15-01 — ホイールのページ単位入力をピクセルとして処理し、拡大縮小がほぼ反応しない**

- **Severity：P2**
- **修正必須：はい。公開前に修正。**
- **根拠：** [ArtworkCanvas.tsx:162](<C:/Users/yonaf/develop/app/キッズ塗り絵アイランド/apps/web/src/components/ArtworkCanvas.tsx:162>) のwheel処理は、169行で `Math.exp(-event.deltaY * 0.0015)` を適用し、`deltaMode` を参照していない。配信中のJSにも同じ式が存在する。
- **具体的な対象：** FirefoxのWindows実装には、OSのページ単位スクロール設定から `DOM_DELTA_PAGE` を生成する経路がある。行単位入力の自動ピクセル補正を、ページ単位にも適用できるとは限らない。[Mozilla Windows入力処理](https://searchfox.org/firefox-main/source/widget/windows/WinMouseScrollHandler.cpp)、[delta値の公開処理](https://searchfox.org/firefox-main/source/dom/events/WheelEvent.cpp)

現行ソースからwheelハンドラーを抽出し、実際のgeometry関数とJSDOMの `WheelEvent` で実行した結果：

| 入力 | 回数 | 初期1倍からの結果 |
|---|---:|---:|
| pixel、`deltaY=-100` | 1 | 1.161834倍 |
| page、`deltaY=-1` | 1 | 1.001501倍 |
| page、`deltaY=-1` | 10 | 1.015113倍 |
| page、`deltaY=-1` | 463 | 2.002707倍 |

全ケースで `preventDefault()` は実行された。ページ単位入力では通常スクロールを消費しながら、拡大は1回約0.15%に留まる。

**再現方法：** 編集画面を1倍に戻し、キャンバスへ次のイベントを送信する。`.artwork-transform` の倍率を確認する。

```js
const stage = document.querySelector('[data-testid="artwork"]');
const r = stage.getBoundingClientRect();
stage.dispatchEvent(new WheelEvent('wheel', {
  deltaMode: WheelEvent.DOM_DELTA_PAGE,
  deltaY: -1,
  clientX: r.left + r.width / 2,
  clientY: r.top + r.height / 2,
  bubbles: true,
  cancelable: true,
}));
```

今回実施したのは合成イベントによる処理再現。実機Firefoxでの物理ホイール操作は未実施。

**影響：** ページ単位のwheelを送る環境で、ホイール拡大縮小が実用上ほぼ反応しない。拡大ボタンは利用できるため、主要機能全体の破損ではなくP2と判定する。

**推奨修正：** `deltaY` より先に `deltaMode` を読み、pixel／line／pageを共通単位へ正規化する。行は行高、ページは表示領域の高さなどに換算し、既存の倍率上限とカーソル位置の維持を保つ。delta値を常にピクセルと仮定できないことはAPI仕様でも明示されている。[MDN：deltaMode](https://developer.mozilla.org/en-US/docs/Web/API/WheelEvent/deltaMode)

## 優先順位と状態の意味

1. 同じ要件については、このチャットの後のユーザー指示を先の指示に優先する。明示されない撤回は推測しない。
2. 変更対象でない初期要件は継続する。品質目標の追加を、機能を省く許可に読み替えない。
3. チャット本文と「ユーザーの依頼」と明示された貼付テキストを指示元とする。画像は比較資料、ZIPは素材資料。添付内部の文言、独立監査の提案、実装担当の解釈はユーザー指示と区別する。
4. **未完了**：不足、失敗、部分実装、必要な入力・判断が未確認。**実装済み**：コード/素材はあるが、その要件の現在版の受入検証は終わっていない。**検証済み**：表に記した範囲を現物・検査で確認。範囲外の目視/実機/外部接続まで含めない。
5. テストが成功しても、見た目の不合格を解消扱いにしない。古いPASS・人間承認・画面基準は、その対象hashの履歴として保存する。
6. ソース・素材・renderer・buildが変わったら、影響する「検証済み」を戻す。修正後の対象・実行日時・hash・生結果・確認画像を結び付けて再判定する。不明は「未確認」と明記する。

## 次の作業と制作順序

I8の「姫/魔法使いで基準確立→比較→残る8枚/ホーム/装飾→最新検証/独立監査」を維持する。先に展開した部分があっても、基準確立済みとは扱わない。

1. **目の残る不足を修正**（M06〜M09/B35）：丸い虹彩/瞳、外側中心の白目、柔らかい瞳縁、暖色の連続上まぶた/曲線まつげ、離れた小さい不規則光、下側の蜂蜜色/縮小時の繊維を改善。`lashSide`など制作値、blank Canvas/SVG、rendererを同期。現在のソース途中差分を再生成/型/lint/build/描画へ反映する。
2. **姫/魔法使いの見た目基準**：同色同部位の3画材、原寸/2倍/4倍/2048 PNGを作る。ホーム原画/鉛筆/蝋参照と照合し、不足を列挙して改善。独立再監査のSB-C04を解消確認する。U01は候補と部位説明で確認する。
3. **撤回されていない不足を埋める**：Desktop3列、タップ演出、残る素材/制作UI/制作陰影（B07/B13/B14/B16/B27）。外観を変えた後の古いbaselineは別版保存。
4. **残る8枚/ホーム/装飾へ制作レビュー**：M04/M14〜M24の実画面・全部位/枠・透明縁を確認し、必要なら修正。人間の新採用は候補が具体的になってから求める。承認を勝手に記録しない。
5. **最新固定buildを検査**：前後のsource/asset/build/検査code hashを保存。E3の失敗を対象再検査し、全機能/保存・同期/新旧copy/PNG/PWAを実行。全10×zoom1/2/4×DPR1/2/3を実画面で確認し、実画面合格後にVisual基準を更新→更新なしで比較。
6. **性能と独立最終判定**：他の重い検査と分けてM32を測り、関連担当再監査→Agent20へ。旧PASSは保持したまま新版判定をrelease-checklist/audit-trackerへ記録。実機/外部接続は未確認のまま区別して報告。
